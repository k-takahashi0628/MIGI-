# 資料A の分類（適用範囲と例外）

- 原文：`references/original/A_オフィシャル記事の負け筋と構成設計.md`（改変禁止・internal）
- この文書は、原文の全項目（第1部 1〜9、第2部 57 項目、第3部）を、どこまで一般化してよいかで分類したもの。原文の知見は一つも落とさず、匿名化して残す。
- 出典の案件は「案件K」（2026年9〜11月の企業公式 note 前後編）、指摘した人は役割名（代表・執行役員・広報担当・進行担当）で書く。実名・社内の数字・事業の具体は書かない。
- 各項目の詳しい中身（NG例・なぜ・回避・見つけ方）は `knowledge/failure-patterns/official-article.md`。

---

## 1. 区分の意味

| 区分 | 意味 | 使い方 |
|---|---|---|
| 基本原則 | どの記事・どの案件にも当てはめる | 例外は原則なし。外すときは理由を台帳の `decisions` に書く |
| 公式記事原則 | 企業の公式記事（採用広報・経営者／社員インタビュー・カルチャー記事・会社紹介）に当てはめる | 個人の寄稿・コラム・ニュース記事では弱めてよい |
| 案件固有 | 案件K の先方の好み・表記・運用。ほかの案件に持ち込まない | その案件の `projects/<slug>/ledger.json` の `rules` に入れて使う |
| 推奨 | 多くの場合よくなる編集上のすすめ | 合わない記事では使わなくてよい。使わないときの理由を言えるようにする |
| 条件付き判断 | 記事の性質（形式・媒体・読み手・シリーズか）で最適解が変わる | 下の「6. 条件付き判断の基準」で決める |

一つの項目に、一般化できる部分と案件固有の部分が混ざっているものは、両方を書いた（例：G1 の「呼び方を揺らさない」は基本原則、「メンバーに統一する」は案件固有）。

## 2. 第1部 構成設計

| 項目 | 主な区分 | 適用範囲 | 例外・判断の分かれ目 | 元の知見（要約） |
|---|---|---|---|---|
| 1. 目的を一文で決める | 基本原則 | 全記事 | なし。軽微な修正の依頼では、既存の目的（`projects/<slug>/work/01_brief.md`）を引き継いで確認するだけでよい | 誰に向けるか／読後の一言の印象／読んだ人の行動を一文ずつ書く。書けないうちは構成を作らない |
| 2. 決めるのは誰か | 公式記事原則 | 先方に決裁者と担当者がいる受託制作 | 自社媒体で編集者が決裁する場合は、決裁者＝編集責任者と書くだけでよい | 最終の決裁者と進行・品質の担当を分ける。意見がぶつかったら決裁者を優先し、担当者の案を消すときは理由を一言添える |
| 3. シリーズの中の役割 | 条件付き判断 | 前後編・連載・同じ会社の既存記事がある場合 | 単発の記事では不要 | 前編・後編・他記事との分担を一文で書く。前の記事の締めで予告した言葉は守る |
| 4. 素材の棚卸し | 基本原則 | 全記事 | なし | 話題を一行ずつ並べ、印象に効くか（◎○×）・前の記事との重なり・根拠・公開可否・取材後の出来事かを付ける。×は入れない。重なりは一言の振り返りに |
| 5. 目的別の章立ての型 | 推奨（型の選び方は条件付き判断） | 公式記事 | 型は出発点。素材と目的に合わなければ型を使わない（下の 6-2） | 経営者（事業）5 章／経営者（組織）7 章／社員インタビュー 6 章／プロジェクト・カルチャー 7 章の型。選んだ型から削る・入れ替える |
| 6. 並べ方：理由→結論、全体→具体、変化→仕組み | 推奨 | 説明・インタビュー記事 | 人物の物語、エピソード先行の導入では、具体→全体の順もありうる | 読者の理解の順に並べる |
| 6. 並べ方：山場は終盤（最後の問いの手前） | 条件付き判断 | 公式記事のインタビュー | 下の 6-3 | 具体的なエピソードを終盤に置く |
| 6. 並べ方：リードの問いに章が順に答える | 基本原則 | リードで問いを立てる記事すべて | リードが問いを立てない形式（ニュース型）は対象外 | リードの問いと章の答えを対応させる |
| 6. 並べ方：締めはリードの言葉を回収／本文にない枠を持ち込まない | 基本原則（持ち込まない）・推奨（回収） | 全記事 | 回収の言葉は言い換えてもよいが、本文にない対比や枠は足さない | 締めの地の文はリードを回収し、本文にない枠（例：新旧の対比）を持ち込まない |
| 6. 並べ方：地の文を本文の途中に挟まない | 公式記事原則 | Q&A 形式のインタビュー | 地の文で進める記事（ルポ型）は対象外。挟むなら見出しのすぐ下 | 地の文はセリフと混ぜず、見出しの下に置く |
| 7. 見出しはその章の答えを言い切る | 推奨 | 公式記事 | 問い型の見出しを使う媒体・シリーズでは、その型にそろえる | 説明調にしない |
| 7. 見出しの型を前の記事にそろえる | 条件付き判断 | シリーズ | 単発では不要 | 前の記事の見出しと同じ構文にする |
| 7. 見出しと章の中身がずれていないか | 基本原則 | 全記事 | なし | 章の中心が別の話なら見出しを変える |
| 7. 問いは前の答えを受けてつなぐ・中身を聞く形 | 公式記事原則 | Q&A 形式 | 対談・座談会では、話し手どうしの受け渡しが問いの代わりになる | 「〜でしょうか」と中身を聞く |
| 7. 一つの章に問いは 2〜3 | 条件付き判断 | Q&A 形式 | 下の 6-4 | — |
| 7. 同じ章で二人が答えるなら話す範囲を分ける | 条件付き判断 | 複数の話し手 | 一人の記事では不要 | 例：一人は事業全体の数字、もう一人は一社ごとの経緯 |
| 8. 長さはシリーズの前の記事と同じくらい | 条件付き判断 | シリーズ | 下の 6-5 | 例：前編 5,600 字なら後編 5,000 字前後 |
| 8. 章ごとの字数の偏り | 推奨 | 全記事 | 山場の章は長くてよい | 山場以外で一つだけ極端に長い章がないか |
| 9. 構成の検査 | 基本原則（チェックの考え方）・公式記事原則（主語の偏り） | 全記事 | シリーズに関する項目はシリーズだけ | 印象に関係しない章／二つの章で同じこと／全章の主語が特定の人たち／山場の位置／リードと締めの対応／前の記事と同じ問い |

## 5. 案件固有のルール（案件K）の扱い

次のものは案件K の台帳に入るべきルールで、ほかの案件には持ち込まない。ほかの案件で同じ判断をするときは、その案件の先方の確認を取ってから、その案件の台帳に入れる。

- 呼称：社内は「メンバー」、加わった人は「新しく加わったメンバー」（G1）
- 表記：WEB／この一年／十年以上／数値は算用数字／うえで／そろう（G2）
- 敬語：社内の人には敬語を使わない、「方」は候補者だけ（A4 の一つの答え）
- 口語・カタカナ口語の NG 一覧（D1・D2）。ハイレイヤー向けのビジネス媒体という条件で決まったもの
- 進め方：清書は新しいタブ、修正箇所は色分け 🟥文言／🟦追加（H1・H2）
- 代表の好み：苦労より、いまある状態・基盤を語る（B2）

## 6. 条件付き判断の基準

記事の性質で答えが変わる項目は、次の手順で決め、決めたことを案件の台帳（`rules` か `decisions`）に書く。一度決めたら、その案件の中では揺らさない。

### 6-1. 敬語（A4）

- **なぜ変わるか**：敬語は「誰が・誰について・誰に向けて」話すかで正解が変わる。経営者が社員について話す場合と、社員が先輩について話す場合では違う。会社の文化（創業者への敬意、顧客への言葉づかい）も関わる。
- **判断の基準**
  1. 話し手の立場：経営者・管理職が自社の社員について話すとき、社員を敬語の対象にすると落ち着かない（案件K の指摘）。社員が上司・先輩について話すときは、本人の口調の敬語を残してよい。
  2. 外の人：顧客・取引先・パートナーには敬語を使う。
  3. 読み手：候補者を指す「方」は使ってよい。社内の人を「方」と呼ぶかは、その会社のふだんの言い方に合わせる。
  4. 先方の決まり：広報の表記規定があればそれが優先。なければ初稿で一つの方針を示し、承認を取る。

### 6-2. 章立ての型（第1部 5）

- **なぜ変わるか**：型は、よくある目的のための出発点で、素材がいつも型どおりにあるわけではない。型に素材を押し込むと、空いた章を一般論で埋めることになる（AI-05・AI-08 の原因）。
- **判断の基準**
  1. 目的と一番の印象を先に決める（`projects/<slug>/work/01_brief.md`）。型は、その印象に向かう順番の候補として選ぶ。
  2. 素材の棚卸しで、型の章ごとに根拠のある話題が一つ以上あるか確かめる。ない章は削るか、要取材にする。
  3. 素材のなかに型より強い筋（一つの出来事の時系列、一つの判断の前後など）があれば、型を使わない。型を使わない判断は `knowledge/editorial-patterns/structure-types.md` の最後に従う。

### 6-3. 山場の位置（第1部 6・F6）

- **なぜ変わるか**：山場を終盤に置くのは、読者に文脈を渡してからエピソードで納得させるため。短い記事、冒頭でつかむ必要がある媒体（SNS からの流入が多い媒体など）、エピソードそのものが企画の入口になる記事では、冒頭に置くほうがよいこともある。
- **判断の基準**
  1. 既定は「最後の問い（期待）の手前」。
  2. 冒頭に置くのは、(a) 全体が 2,000 字程度より短い、(b) エピソードが読む理由そのもの、(c) 媒体の読者がタイトルとリードで離脱しやすい、のどれかに当たるとき。その場合も、終盤で同じエピソードの意味を回収する。
  3. 山場が素材にないとき、作らない。追加取材の質問にする（`knowledge/editorial-patterns/interview-craft.md`）。

### 6-4. 問いの数（第1部 7）

- **なぜ変わるか**：問いの数は、章の長さと話し手の数で変わる。問いが多いと細切れになり、少ないと答えが長くなって流れが見えにくい。
- **判断の基準**
  1. 既定は 1 章に 2〜3。
  2. 章が 600 字程度より短いなら 1〜2、話し手が二人いて範囲を分けるなら 3〜4 もありうる。
  3. 数より、問いが前の答えを受けてつながっているか（E1〜E3）を優先する。
  4. `python3 scripts/aco structure` で章ごとの数を出し、偏りを見る（数は目安で、判定ではない）。

### 6-5. 文字数（第1部 8・F7）

- **なぜ変わるか**：適切な長さは、媒体（note・Wantedly・自社サイト・ホームページの短いメッセージ）、読み手の時間、シリーズかどうかで変わる。
- **判断の基準**
  1. シリーズなら、前の記事と同じくらい（±20% 程度）。`aco structure --compare <前の記事>` で比べる。
  2. 単発なら、目的と素材で決める。素材が足りないのに字数に合わせて伸ばさない。
  3. 媒体の決まりがあればそれに従う（例：ホームページの短いメッセージは見出し＋本文 250 字前後。`knowledge/approved-lessons/lessons.json` の承認済みルール）。
  4. 山場以外で一つだけ極端に長い章がないかを見る。

### 6-6. 表記統一（G1・G2）

- **なぜ変わるか**：揺らさないことは全案件の原則だが、**何にそろえるか**は会社の表記規定・前の記事・媒体で違う。ある案件で決まった表記（例：WEB）は、別の案件では Web が正しいこともある。
- **判断の基準**
  1. 先方の表記規定 → 同じ会社の前の記事 → 媒体の慣例 → 一般的な表記（記者ハンドブックなど）の順で決める。
  2. 決めた表記は案件の台帳 `rules`（`avoid` と `use`）に入れる。`aco ledger <slug> check` と `aco audit --project <slug>` が揺れを拾う。
  3. 別の案件の表記を持ち込まない。

### 6-7. 口語・カタカナ口語（D1・D2）

- **なぜ変わるか**：経営者・管理職向けのビジネス媒体では、口語は稚拙に見える。一方、社員の素顔を見せる記事や若い候補者向けの媒体では、話し言葉がその人らしさになる。
- **判断の基準**
  1. 地の文：書き言葉にそろえる（どの媒体でも）。
  2. 発言：媒体のトーンと読み手で決める。ハイレイヤー向け・公式色の強い媒体は書き言葉に寄せ、社員ブログ型は話し言葉を残す。決めたら台帳に書く。
  3. どちらの場合も、話し手が言っていない内容を足さない。口調を直すことと、内容を変えることを混ぜない（`knowledge/editorial-patterns/quote-editing.md`）。

### 6-8. 言い切り（D3）と言い過ぎ（C4）の両立

- 根拠のある所は言い切る（「土台は、データです」）。
- 根拠のない所を言い切ると言い過ぎになる。範囲と数は、根拠の言葉どおりに書く。
- 話し手の迷いそのものが内容（判断の難しさを語る場面）なら、ぼかしを消さない。

## 7. 匿名化について

原文の NG 例のうち、次のものは一般化して `knowledge/` に載せた。原文の言葉が要るときは原文（internal）を開く。

- 社内の数字（作業時間の短縮幅など）→「社内の作業時間の短縮幅」
- 社内の会議名・施策名 →「社内の会議の名前」
- 会社の事業構造や集客の仕組み →「出したくない事業構造」
- 先方の事業を表す言葉を含む例 → 同じ型の別の例
- 代表の参画年 →「途中から参画した代表」
- 実際の対象範囲（特定の役職者全員）→「実際は一部の役職者だけ」

# 失敗の型（索引）

| ファイル | 中身 | ID |
|---|---|---|
| `knowledge/failure-patterns/official-article.md` | 企業の公式記事が差し戻される型（資料A 第2部を匿名化・一般化） | A1〜A6・B1〜B7・C1〜C8・D1〜D13・E1〜E7・F1〜F7・G1〜G4・H1〜H5（57 項目） |
| `knowledge/failure-patterns/ai-writing-signs.md` | AI 文章の兆候（資料B の観察を日本語の企業記事に当てはめたもの） | AI-01〜AI-17 |

## 使い方

- 書いた後・直す前に、`knowledge/failure-patterns/official-article.md` を上から順に当てる（負け筋 H4）。
- 機械で拾える候補は `python3 scripts/aco audit <file>` が出す。拾うのは候補だけで、当たっているかは文脈で決める。
- どこまで一般化してよいか（基本原則・公式記事原則・案件固有・推奨・条件付き判断）は `references/derived/A_classification.md`。
- レビュー票（`projects/<slug>/work/reviews/`）では、指摘に必ず ID を付ける（例：`A1` `AI-06`）。

## 機械で候補を拾えるもの（`aco audit`）

| ID | 拾い方 |
|---|---|
| A1 | 「新しく／新たに加わった・中途・経験者」と「これまでの・既存・生え抜き」が同じ段落・記事に対で出る |
| B1 | 「迷うことはなかった」「手をつけられていない」「やりきれなかった」など |
| B5 | 「必ず」「絶対」「一番」「No.1」「ゼロ」「唯一」など |
| C4 | 「全員」「すべて」「格段に」「最も」「圧倒的」など |
| C7 | 「そこで」「だから」「その結果」など（AI-15 と同じ） |
| D1〜D6 | 口語・カタカナ口語・弱い文末の回数・近くの繰り返し・類語の使い回し・作った型 |
| D9 | 長すぎる文・読点の多すぎる文 |
| D10 | 「たとえば」の文に数字・固有名・場面の語がない |
| D13 | 「そのまま」「すぐに」 |
| E1 | 問いの行が「〜ますか」「〜ですか」「気になります」で終わる |
| G3 | 問いの記号「── 」の空白、疑問符の揺れ |
| G1・G2 | 案件の台帳の表記ルール（`--project <slug>` を付けたとき） |
| AI-01〜AI-17 | `knowledge/failure-patterns/ai-writing-signs.md` の「検出」の欄 |

上のほかは人（担当のエージェント）が読んで判断する。

## 新しい型を足すとき

- 案件で新しい指摘を受けたら、feedback-learning で候補に挙げる。承認されたら、案件固有なら台帳へ、全体に通用するなら `knowledge/approved-lessons/` へ入れる。
- この 2 つのファイルの番号は変えない（レビュー票や台帳が参照している）。足すときは末尾に新しい番号を付ける。
- 資料A の原文（`references/original/`）は書き換えない。

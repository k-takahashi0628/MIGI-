# 具体性の作り方

具体性は、文章の技術ではなく素材から生まれる。抽象を具体に置き換えるとき、具体を作らない。

---

## 1. 抽象を見つける

次の文は、具体が足りない疑いがある。

- 社名と人名を入れ替えても成り立つ文
- 抽象語（挑戦・成長・価値・可能性・想い・魅力・やりがい・寄り添う）が主語か目的語になっている文（AI-05）
- 「さまざまな」「多くの」「大きな」「数多くの」で量をぼかした文
- 「たとえば」のあとに場面がない文（負け筋 D10）
- 重要さ・意義だけを言う文（AI-01・AI-02）

`python3 scripts/aco audit <file>` が候補を拾う。

## 2. 置き換える手順

1. **問いに直す**：抽象の文ごとに、読者が聞きたくなる問いを書く。
   - 「挑戦できる会社です」→「何に、誰が、どう挑戦したのか」
   - 「お客様に寄り添う」→「どの客の、どの困りごとに、何をしたのか」
2. **素材で答える**：`projects/<slug>/work/02_source-audit.md` から、その問いに答える発言・事実・数字を探す。
3. **答えで書き直す**：見つかった事実を文の主役にする。抽象語は、要らなくなれば消す。
4. **見つからなければ**：次の 3 つから選ぶ。どれを選んだかをレビュー票に書く。
   - **削る**：その文がなくても記事の目的が果たせる
   - **要取材**：`【要取材：…】` を置き、追加取材の質問を作る（`knowledge/editorial-patterns/interview-craft.md` 4 章）
   - **構成を変える**：その章そのものが素材不足なら、章を削るか、ほかの章に統合する（story-architect に戻す）

## 3. 具体の種類

| 種類 | 例（架空） |
|---|---|
| 数 | 「契約は 3 年で 12 社から 40 社に」 |
| 場面 | 「朝 7 時、出荷前の検査台で、佐伯（架空）は 1 台ずつ電源を入れる」 |
| 判断 | 「納期を 1 日延ばしてでも、全数を測り直すと決めた」 |
| 本人の言葉 | 「止めない工場より、止めて直す工場のほうが強い」（書き起こしにある言葉） |
| 固有の道具・仕組み | 「点検表は A4 一枚。項目は 7 つに減らした」 |
| 比較（自社の過去と） | 「以前は手書きの記録を翌朝まとめていた」 |

比較は自社の過去と比べる。他社や他の社員と比べて下げない（負け筋 A3）。

## 4. やってはいけないこと

- 素材にない数字・場面・顧客名を「例として」書く。例でも、記事に書けば事実として読まれる。
- 一般的な業界の話を、その会社の具体のように書く。
- 具体を足すために、話し手のセリフを作る（`knowledge/editorial-patterns/quote-editing.md`）。
- 抽象語を、別の抽象語に言い換えて終わる（「価値を提供」→「貢献する」）。

## 5. 抽象語を残してよいとき

- 話し手が実際にその言葉を使い、すぐ後に具体が続くとき。
- 会社の理念・行動指針の正式な文言を引くとき（出典を示す）。
- 具体を積み上げた後に、一度だけまとめの言葉として置くとき（途中の総括にしない。AI-10）。
